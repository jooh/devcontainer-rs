# Native Feature Test Command

`devcontainer features test` is implemented in Rust and exercises local Feature projects through the configured container engine. It does not delegate to the upstream TypeScript test runner.

The command expects a project folder with `src/` and `test/` directories:

```text
.
|-- src
|   `-- my-feature
|       |-- devcontainer-feature.json
|       `-- install.sh
`-- test
    |-- _global
    |   |-- scenarios.json
    |   `-- global-scenario.sh
    `-- my-feature
        |-- test.sh
        |-- duplicate.sh
        |-- scenarios.json
        `-- scenario-name.sh
```

## What Runs

- `test/<feature>/test.sh` creates an autogenerated test for that Feature unless `--skip-autogenerated` is set.
- `test/<feature>/duplicate.sh` creates a duplicate-install test unless `--skip-duplicated` is set.
- `test/<feature>/scenarios.json` creates named scenario tests unless `--skip-scenarios` is set.
- `test/_global/scenarios.json` creates global scenario tests when no Feature filter is active.

Each discovered case is materialized into a temporary workspace. The native runner writes a generated Dockerfile, copies the selected Feature sources, runs each Feature `install.sh`, starts a container, and executes the matching test script from `/workspace`.

By default the runner removes test containers and temporary workspaces after each case. Use `--preserve-test-containers` to keep containers for inspection.

## Supported Options

Use long option names for scripted workflows:

```bash
devcontainer features test \
  --project-folder . \
  --features my-feature \
  --base-image docker.io/library/debian:bookworm-slim
```

Current native options include:

- `--project-folder <path>`: project root containing `src/` and `test/`.
- `--features <name>`: run one Feature directory by exact name.
- `--filter <text>`: keep only discovered test names containing the text.
- `--base-image <image>`: base image for autogenerated and duplicate tests.
- `--remote-user <user>`: user passed to container exec for test scripts.
- `--global-scenarios-only`: only run `_global` scenarios.
- `--skip-scenarios`, `--skip-autogenerated`, `--skip-duplicated`: disable discovery modes.
- `--permit-randomization`: allow alternate duplicate-test option values to be picked with randomness.
- `--preserve-test-containers`: keep containers after tests.
- `--quiet`: suppress the local summary report.

## Scenario Support

Scenario entries are read from `scenarios.json` as JSONC. A scenario can set:

- `image`: base image for the generated Feature test image.
- `build.dockerfile` and `build.context`: build a scenario base image first.
- `features`: local Feature IDs by name, or published-style Feature references known to the repo-owned offline catalog.

Relative Feature references such as `./feature` are not supported by the native runner today. Use the simple local Feature name, for example `my-feature`, for `src/my-feature`.

## Test Helper

The runner writes `dev-container-features-test-lib` into every temporary workspace. It provides the upstream-style helpers used by many Feature tests:

- `check <label> <cmd> [args...]`
- `checkMultiple <label> <minimumPassed> <cmd>...`
- `reportResults`

Using the helper is optional; any script exit status of `0` passes the case.
